# Phase 0 baseline — 2026-10-21

The "before" numbers for real-user model calls, taken once every call went through
`services/llm_service.py` and was logged to `llm_calls`. Later changes (gateway features,
model routing, prompt changes) are measured against this.

## Setup

| | |
|---|---|
| Data window | 2026-10-20 07:59 → 2026-10-21 11:06 UTC (`eval_run_id IS NULL`) |
| Sample | 22 entries: 20 fictional entries from `scripts/seed_entries.py` + 2 entered by hand |
| Execution | Analyzed one at a time (no concurrent calls) |
| `analyze_entry` | `anthropic/claude-sonnet-5-5`, effort `high`, $2.00 / $10.00 per MTok in/out |
| `recommend_exercises` | `anthropic/claude-haiku-5-5`, effort `low`, $0.10 / $0.50 per MTok in/out |
| Prompt caching | Off |
| LiteLLM | 1.103.3 |

## Per entry

| Metric | Value |
|---|---|
| Entries analyzed | 22 |
| Total cost | $0.2297 |
| **Cost per entry** (both calls) | **$0.010441** |
| Avg tokens, analyze_entry | 2,725 in / 424 out |
| Avg tokens, recommend_exercises | 1,282 in / 628 out |

The two calls run in sequence, so end-to-end analysis time per entry is roughly the sum of
the two task latencies, about 8 s at p50.

Query used for this table:

```sql
SELECT
    COUNT(*) FILTER (WHERE task = 'analyze_entry' AND status = 'success') AS entries_analyzed,
    ROUND(SUM(cost_usd), 4) AS total_cost_usd,
    ROUND(SUM(cost_usd) / NULLIF(COUNT(*) FILTER (WHERE task = 'analyze_entry' AND status = 'success'), 0), 6) AS cost_per_entry_usd,
    ROUND(AVG(input_tokens) FILTER (WHERE task = 'analyze_entry')) AS avg_in_analyze,
    ROUND(AVG(output_tokens) FILTER (WHERE task = 'analyze_entry')) AS avg_out_analyze,
    ROUND(AVG(input_tokens) FILTER (WHERE task = 'recommend_exercises')) AS avg_in_rec,
    ROUND(AVG(output_tokens) FILTER (WHERE task = 'recommend_exercises')) AS avg_out_rec
FROM llm_calls
WHERE created_at > now() - interval '7 days'
  AND eval_run_id IS NULL;
```

## Caveats

- **Small sample.** With 22 attempts per task, p95 is interpolated between the two slowest
  calls, so expect it to move by seconds between runs.
- **No failures or retries.** Every attempt succeeded on the first try, so this baseline says
  nothing about cost or latency under errors.
- **Fictional entries.** They are 61–164 words, so input tokens are dominated by the system
  prompts. Longer real entries would cost more.
